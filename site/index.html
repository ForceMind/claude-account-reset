01 / 边界

重置登录状态，保留历史文件。

按需清理

账号与认证状态

已知 OAuth 字段、Cookie、上次账号提示、同步归属，以及配置恢复日志。扩展模式还清理已知账号功能缓存和遥测。

保护并校验

对话与本地工作

已知会话目录、附件和文件历史校验前后一致；保留 Local Storage 中的会话索引、草稿、预设与未知记录。

这不是账号迁移或全盘痕迹擦除。保留的会话可能含账号引用；新账号能否显示旧历史取决于 Claude。未知认证格式、IndexedDB 与 Session Storage 不做盲目删除。

03 / 恢复本地历史

列表不见了，正文可能还在。

新增索引 · 保留原件

恢复 Code 对话

先登录目标账号并进入 Code，再退出 Claude。工具匹配已有索引与本地正文，备份目标目录后仅新增缺失记录。已有记录跳过，归档状态保留；工作目录缺失会单独报告。

兼容性边界

旧 thinking 不一定能跨组织使用

恢复预览统计 thinking 和带签名的思考块，完整保留正文。账号绑定的旧思考可能被 Claude 丢弃并重新生成，增加等待时间和 token 消耗。列表恢复不等于旧思考可复用。

当前恢复支持本地 Code 索引，不自动迁移 Cowork 或云端聊天。恢复会话使用手动权限、远程控制关闭。请将 recovery-backups 和报告保留在本机，不上传。

04 / 理解每一步

知道为什么删，也知道留下什么。

为什么要清理配置恢复日志？

config.json.journal 是配置写入和恢复使用的日志。只改主配置可能让旧状态恢复。工具配套删除日志，并回读主配置验证目标字段。

为什么 Local Storage 不能整个删除？

它混合存放账号提示、同步身份、界面设置、会话索引和草稿。工具仅匹配已知来源与键名，校验其他记录字节不变，再压缩失效旧记录。数据库压缩不等于安全擦除。

和 MultiClaude 的隔离原理有什么关系？

MultiClaude 通过独立数据目录分开账号。这提示检查不应限于默认 Claude 目录。本工具检查相邻 Claude-* 目录，但不会把整个目录视为凭据，也不依赖安装 MultiClaude。

“不能使用另一个组织的 thinking”是没清干净吗？

这指向保留历史中的账号绑定推理块，不能证明旧登录仍有效。工具只统计、不删除或重签 thinking。Claude 可能跳过它们，重新推理。阅读官方说明。

数据会上传吗？

网页没有上传入口、第三方统计或外部脚本。安装时访问下载站与 npm；清理工具本身不发送网络请求。本地报告可能包含路径和字段名，分享前请检查。

清理失败或版本变化怎么办？

遇到运行中的 Claude、符号链接、损坏配置或数据库错误时停止。跨文件清理不具备全局事务性，已完成的删除不会自动回滚。规则依据 Desktop 4.29.0，不承诺其他版本完全覆盖；未知字段保留。
