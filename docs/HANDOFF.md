# v0.4 Thinking 清理与接手文档

handoff是独立的正文转换，必须先保存并审阅计划。它会影响所有使用所选正文的profile。

```sh
node bin/handoff.mjs --protect-since 2026-11-02 --time-zone Asia/Shanghai \
  --plan-out handoff.plan.json
node bin/handoff.mjs --execute handoff.plan.json --yes
```

日期仅为示例。未选日期参数时不自动过滤近期活动；可再用会话白名单、排除名单及历史基线限定。

## 转换

逐行读取JSONL，最多8MiB一行，UTF-8必须有效。仅移除message.content中的thinking/redacted_thinking及块内签名；未识别的思考布局拒绝处理。其他字段、工具关联和UUID链按语义哈希验证。只包含思考的消息保留结构及空content，具体客户端兼容性未实机验证。

接手文档由用户消息、可见回答、工具输入和结果按原顺序组成，以足够长的Markdown文本代码围栏避免历史内容改变文档结构。它不是任务完成情况的自动总结，历史指令不是当前执行授权；二进制附件不嵌入。

同名完全相同正文去重为一个逻辑会话。长短快照分别转换，不将长本覆盖短本；文档来自长本。双方各有独有消息时跳过，不能制造合并历史。

## 流式资源与备份

规划阶段统计输出/文档大小，不把整批正文放入内存。执行阶段先完整备份并回读，再逐文件生成暂存正文与文档，确认可见记录不变。目标安装后再次核对保护集合。

`--discard-backup`必须在生成计划时选择。全部本地检查成功且没有未解决候选项时才删除本批次，失败保留；它不会等待真实模型回答验证。希望保留人工验收机会时，不选该参数。

## 组织与隐私

[官方 preserved thinking 说明](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)区分模型、历史前缀及账号绑定。删除已知块不改变服务端识别账号/设备的能力，也不保证其他格式、压缩上下文或产品缓存不再触发提示。不能通过伪造签名绕过机制。

计划、正文备份和文档都私有。文档仍可能包含可见历史中的凭据、路径和个人信息，分享前审阅，不自动上传。失败后依据journal和恢复预览处理，不能整目录覆盖后来产生的新会话。
