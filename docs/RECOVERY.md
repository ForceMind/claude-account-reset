# v0.4 本地 Code 会话恢复

Desktop索引通常按账号和组织存放，正文由Code保存到projects下的JSONL。换账号后正文可能仍在，但新账号列表没有索引。恢复只增加缺失的最小本地索引，不转移云端归属，不处理Cowork。

## 操作

```sh
node bin/recover.mjs --plan-out recover.plan.json
node bin/recover.mjs --execute recover.plan.json --yes
```

先登录目标账号并初始化Code目录，再退出。`--source`选择Desktop来源，`--target`选择目标，`--code-dir`明确选择正文配置目录，`--org`用于组织歧义。

计划列出Desktop ID、CLI ID、标题、当前目标关联、工作目录与归档状态。按`--session`/`--exclude`精确选择。`--protect-since`必须配合明确`--time-zone`；缺少有效用户时间也保护。`--baseline`保护新建、正文/索引变化和CLI关联变化。

同一Desktop会话改指向新CLI日志时，不能把旧日志的长度当成选择依据。默认保护多CLI关联，除非用户选择具体CLI ID。已有目标索引不被覆盖。

同ID正文按字节关系分类：相同、短本为长本前缀、真正分叉。前缀快照可以分别处理，以长本导出完整历史；分叉不自动合并。不存在正文、未知结构或目录异常会跳过/停止并报告。

## 保护

新索引使用字段允许清单，排除旧连接器、云端桥接和待执行动作，权限手动、远程控制关闭。每次实际写入都由统一执行器完成；备份、源哈希和新文件独占创建防止覆盖其他会话。

恢复模式完整保留thinking。只统计签名与块数量，不解密、不重签，不能证明跨组织可复用。`uiVerified`和`modelVerified`保持false。

## 历史证据及边界

此前一次受控手工流程恢复了50条索引，检查过侧边栏并抽查一条正文；后来实际续聊出现旧组织thinking提示。因此，显示历史与旧推理可复用必须分别报告。这个手工证据不能视为v0.4在真实账号上的验收。

新版使用合成数据重现50条会话、近期活动、额外新会话、索引变化和不同副本，不操作原用户的会话。原实际项目中发现的较短快照，以及续接后变更CLI ID的情况，已纳入测试。
