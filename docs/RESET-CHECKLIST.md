# Windows Claude 重置检查清单

先记录安装方式、版本、资料根和批准范围。用同一范围记录执行前后状态。界面出现登录提示、活动目录为空、保留历史仍能阅读，各自需要独立证据。

| 检查点 | 记录或核对 |
| --- | --- |
| Desktop 布局 | 当前用户的包注册和应用版本。核对已存在的 `Claude-Data/<family>`、`Packages/<family>` 下的活动数据槽、用户 Roaming 和 Local 的 `Claude`、`Claude-3p`；根据启动方式确认路径归属。仅目录名或空目录不足以确定实际资料根。 |
| Code 布局 | 默认 `.claude`、用户根 `.claude.json` 及备份副本、凭据文件和有效的 `CLAUDE_CONFIG_DIR`。单独核对系统与用户环境、项目设置、启动脚本和 helper；报告字段名，省略值。 |
| 浏览器型存储 | 记录 Cookie 的域和已确认的名称。核对数据库事务文件、配置恢复日志、Local/Session Storage、IndexedDB、索引、扩展授权和设备记录。按有效记录判断，区分失效页、压缩或加密内容和未验证项。 |
| 本地标识 | 检查已知旧账号、组织 UUID 在结构化键和值、自由文本、目录名和索引中的引用。另看 `userID`、`machineID`、`Local State`、`ant-did`、远程控制身份及扩展授权。字段变化无法验证硬件身份、外部归因或服务端撤销。 |
| 独立凭据 | 核对 Windows 凭据管理器、API 或 OAuth 环境覆盖、组织托管状态。多账户工具的隔离目录可能共享默认目录或系统凭据，按实际启动路径检查。 |
| 受保护历史 | 查正文、工具记录、附件、文件快照、工作区与技能文件，以及外部引用。复制目录、显示索引和原生续接分别验收。明确归档读回范围，二进制按原字节保存。 |

## 历史 Windows 审计经验

- 一次 Windows 检查里，`ccd-session-store` 的有效记录只有运行状态与旧 `state.orgUuid`，未发现正文或附件。检查过的 Cowork 范围无聊天正文，仍有工作区和技能文件，目录名含身份引用。结论限于当时查过的目录和版本。
- Chromium IndexedDB 的 `idb_cmp1` 比较器需要适配解析，普通 LevelDB 工具无法可靠修改。一次检查中有效的三条应用值仅为时间戳。应先只读核实实际记录，再在单独批准的完整重置范围处理整个资料槽。Cookie 表名和键名需要结合具体语义与域名判断。
- MSIX 原生命令曾以非零状态退出；当时 AppX 事件、当前用户的包注册及实际资料目录显示重置阶段已经生效。先核对三项证据，再决定是否重试。真实应用身份由首次启动单独确认。 [Microsoft Reset-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/reset-appxpackage)
- Windows 沙箱可以重定向 `LOCALAPPDATA`。当 Windows 已知文件夹、注册表、环境变量或实际解析路径无法相互印证时，记录未验证并停止写入。

## 处置前回读

1. 审阅活动路径和数据类型。包数据、第三方 profile、其他软件、浏览器、云端、系统快照和项目文件分别划界。
2. 将归档存入仓库之外的私有目录，核对权限、正文与工具记录、附件和文件历史清单及 SHA-256。保留不透明内容的未验证标记。
3. 复查活动目录、包注册和应用身份。当文件仍被占用或出现新数据时，保留回滚原件，避免盲重试或覆盖。
4. 只有归档完整性、实际重置状态及保留档案再次读回均通过，且用户已授权，才处置含旧 ID 的原件。发布材料只用合成示例，不包含真实正文、凭据、原始 ACL、完整本机路径或私有映射。
