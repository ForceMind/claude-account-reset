# 本地账号状态清理：经验与原理

本文把一次 Claude Desktop 4.29.0 的清理流程整理为通用经验，不包含真实账号标识、会话内容、凭据或本机报告。

## 1. 先定义目标

“退出旧账号”“尽量减少旧账号痕迹”“像新 profile 一样从独立目录启动”“保留会话文件”是不同目标。清除登录材料可以同时保留会话；保留会话会留下其中的账号引用。不要把规则检查通过说成全机痕迹为零。

## 2. 多账号隔离反推检查范围

[MultiClaude 的 Profile 实现](https://github.com/QuentinCar0n/multiclaude/blob/main/main.swift)通过 `--user-data-dir` 隔离 Desktop 数据目录，通过 `CLAUDE_CONFIG_DIR` 选择 Code 配置；实际代码还允许固定的自定义 codeDir。只检查默认目录会遗漏其他 profile。

该项目自动发现 `Claude-*` 时明确排除 `Claude-3p`。本机 Claude 程序也把这个名称列为可能的数据目录，所以不能仅凭目录名判断它属于用户自行建立的第二账号。工具检查它，但不删除整个目录。

MultiClaude 的 ChatLimits 实现从 profile 的 `Cookies` 数据库读取 `sessionKey`，用 `Claude Safe Storage` 解密，再请求 claude.ai。这个实现给出一条明确的登录读取路径，**不是 Claude 所有认证机制的完整规范**。

参考源码为 2026-10-29 所见 main 分支；上游行号与实现会变化。本工具没有复制其 Swift 代码，不调用该用量接口，也不解密凭据。

## 3. 各类状态的意义

- `lastKnownAccountUuid`：记住上次登录者，不等于密码或有效凭据。删除可避免沿用旧账号提示。
- `config.json.journal`：配置写入/恢复日志。只改主配置可能被旧日志恢复，需配套处理。日志格式不是普通 JSON 时不要随意字符串替换。
- Cookie：可能含认证会话与设备信任信息。空库没有认证材料，删除空库只是重置存储。
- `__qk_hint_account_uuid`、`rq-cache-confirmed-account`：账号提示/缓存归属标识；`ccd-sync-owner/org/active` 关联同步身份。精确清理它们，同时保留 `ccd-session-store`。
- `lastLoginMethod`、first-login 标记：登录 UI 的记忆。删除会影响提示和引导，不能撤销服务器 token。
- 遥测队列、匿名 ID、退出标记：普通换账号不一定需要删除。仅在明确要求减少旧状态时清理。
- 加密钥匙串项：通常是共享的应用加密材料。删除会影响其他 profile 的已加密凭据，必须独立选择。

实际一次清理曾删除 17 条账号/登录/遥测记录，但 **17 不是规则、阈值或每台机器的预期数量**。工具按键名与来源计算当前计划。

## 4. 数据库的“已删除”与磁盘残留不同

对 .ldb 做字符串搜索会看到失效旧版本，也可能漏掉压缩、编码数据。先使用数据库引擎读取有效键值，再精确删除，比较保留记录，最后压缩整理旧记录。压缩不是取证级擦除，文件系统快照和备份不受影响。

直接复制正在运行的 LevelDB 也不是可靠的一致性快照。先退出 Claude；只读检查使用临时副本并及时删除，原数据库不打开写入。临时副本可能包含敏感内容，因此只放本机私有临时目录，不上传或长期保留。

## 5. 成功需要说明证据边界

清理前定位账号配置、会话和备份。清理后回读目标字段、检查钥匙串状态、校验受保护文件与保留的键值。错误必须停止并如实报告；多文件清理不是全局事务。避免为“可回滚”复制旧 token 到其他地方。

“会话文件未变化”不表示新账号可以查看旧账号的云端历史；“没有 sessionKey”也不等于所有认证机制都已排除。本工具保留 IndexedDB 与 Session Storage，明确不保证账号痕迹全部消失。

## 6. 换账号后的索引恢复与 thinking

账号状态清理、会话索引恢复、旧思考可复用是三个独立条件。0.2.0 提供独立恢复命令：新增目标索引、保留原件、按 CLI 会话 ID 去重；同时检测并保留 thinking，明确跨组织兼容性未经验证。具体经验及边界见 [RECOVERY.md](RECOVERY.md)。
